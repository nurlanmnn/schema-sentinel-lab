# Fresh model screening cases

Five synthetic, public, Distribution A migrations on the existing testbed. These belong to `fresh_screen`, separate from both development and held-out evaluation. No model was called, no raw model response was inspected, and no performance evidence was used to select or shape these cases. The required README and the reserved-case plan contain aggregate results; that exposure prevents a claim of complete ignorance of all aggregate history. No linked result reports or observed-outcome sections were consulted. The H1–H8 changes remain unspent.

All cases pin baseline commit `3fe9f2d0512812216f47c1b89c7e9bd28e102d57`. No baseline runtime, proto, dependency, generated binding, or testbed-test changes are required in this checkout. The host pub/sub broker adds opt-in nullable observation fields for the fresh oracle; its default contract stays string-only. The host pub/sub runner accepts an explicit sample provider so fresh vectors do not alter the development case registry. Each proposal changes one proto and runtime source in Python, TypeScript and C#. Bindings are regenerated by the normal validation gate, never patched by a proposal.

## Running and sealing

`run_demo.py --case <id> --local-codegen --output NEW_DIRECTORY` uses the deterministic reference recipe through the same pipeline, isolated patch application, code generation, build/unit/round-trip checks, independent oracle, and human-review exporter as a live patch. `--response` can replay each stored wrong patch through that same gate. It takes a proposal JSON envelope: put the patch text in `diff`, with `contract_version="1.0"`, `outcome="patch"`, a nonempty `rationale`, `confidence=0`, and `assumptions=[]`; pass that JSON file to `patchgen.pipeline --response` together with the fixture, `--local-codegen`, and a new output directory. None counts as model success.

After review, an operator may run `.venv/bin/python -m patchgen.fresh_manifest seal`; **seal has not been run during authoring**. It writes `fresh-screen/manifest.json`. `verify` recomputes file membership and SHA-256 hashes for all fixture/reference/control files, oracle and harness code, codegen configuration, and both working and pinned baseline dependencies, plus `patchgen/pipeline-requirements.txt` and `live_suite.prompt_fingerprints()`. Each case also records the SHA-256 of its prepared input and each exact rendered `candidate_semantic_blocks` message list, rebuilt offline through the detector, locator and fresh adapter with the pinned source. Prompt hashes use the same `json.dumps(messages).encode()` bytes as the generator. The Python module inventory is limited to modules imported by the fresh generation/validation, review and manifest routes; unrelated recipes and analysis scripts are excluded. New files and changed, removed or symlinked dependencies fail verification. The manifest is an integrity record, not an externally authenticated signature. Keep its digest independently if that assurance is needed.

`live_suite --fresh --sample N --output NEW_DIRECTORY` runs exactly `FRESH_CASES`. It supports the existing non-locked backend/model/strategy choices and `--locked`. It refuses combinations with `--held-out`, `--case` or `--full-benchmark`. Individual fresh IDs can instead be selected using `--case`; these selections also require verification. Verification happens before credentials or model requests. Each result is labelled `fresh_screen`, and `validated_by_split` keeps all selected cases in its denominator even when a provider error stops execution. The 20-case `run_benchmark.CASES` development set is unchanged.

`--sample N` is a required 1-based sample index for `--fresh`. Before credentials or model requests, the runner appends a reservation to `fresh-screen/attempts.jsonl` with a UTC timestamp, backend, model, strategy, sample, output directory and manifest digest. The ledger locks across concurrent writers. A second attempt for the same `(model, strategy, sample)` is refused unless a nonempty `--rerun-reason` is supplied. Reruns append a flagged record pointing to the original attempt and use a new output directory; they never replace the original. A credential or infrastructure failure after reservation still consumes the attempt.

Request timeouts, connection/TLS failures, HTTP errors (including 429 and 5xx), provider error envelopes and empty/incomplete provider responses receive explicit infrastructure stages. `finish_reason=length` (or Ollama `done_reason=length`) receives `truncated_at_token_limit`, reported as a separate model-and-budget outcome. Summary counts separate `infrastructure_failures`, `truncated_at_token_limit` and `model_failures`, while the planned-case denominator retains every case. Existing locked development request/stop behavior and sampling stay unchanged; the additional failure labels describe those outcomes.

## Cases

### fresh-entity-name-presence

- Domain: pubsub/entity. Label: **semantic**.
- Change: Explicit presence for v1 name.

**Intended behavior (verbatim fixture policy)**

Add explicit presence to v1 Entity.name at field 2. Each relay and pub/sub subscriber must observe an absent name as JSON null and a present name as its exact string, including an explicitly present empty string. Preserve entity_id, Unicode, whitespace and escaped text exactly. Preserve name presence and value when relaying encoded messages; the standalone sample producers still set their existing nonempty names. v2 has no name and must keep its existing entity_id-only observations. Do not edit tests or generated bindings. Coordinated rollout only; legacy writers cannot distinguish an omitted empty name from absence.

**Oracle**

Absent versus explicit empty name, duplicate-tag last-value behavior, long UTF-8 lengths, Unicode, whitespace, escaping, and unchanged v2 observations. The production gate checks 12 publications × 3 independent subscribers and rejects a malformed wire payload in every subscriber. It also checks eight independent v1 relay requests (24 decoder observations) and the exact returned wire, including absent and explicitly empty names after serialization. Total: 60 runtime observations.

**Wrong patches**

- `wrong-forgot-csharp.patch` (oracle): C# retains the baseline default/presence behavior and fails the all-runtime oracle.
- `wrong-empty-is-absent.patch` (tests): Conflates explicitly present empty names with absence. In the full pipeline the existing end-to-end round-trip test rejects it before the fresh oracle runs; checked alone, the fresh oracle also rejects it (corrected after an unsandboxed run; it was first labelled oracle).
- `wrong-absent-is-empty.patch` (oracle): Defaults an absent name to empty text instead of JSON null.

**Weakness**

The standalone producer samples are fixed nonempty names; arbitrary application producers are outside this testbed. Old writers cannot represent explicit empty presence.

### fresh-telemetry-speed-presence

- Domain: telemetry. Label: **semantic**.
- Change: Explicit presence for speed_mps.

**Intended behavior (verbatim fixture policy)**

Add explicit presence to VehicleTelemetry.speed_mps at field 2. request.speed may be missing or null, in which case producers omit speed_mps; any supplied number within the finite float32 range, including zero, must be explicitly present after float32 serialization. Consumers expose speed_mps as JSON null when absent, otherwise the decoded float32 value as a JSON number; any decimal form that rounds to that float32 is accepted. speeding is true exactly when speed_mps is present and greater than 30.0; missing, zero and negative values are not speeding. Preserve vehicle_id, including empty and Unicode identifiers. Producer input and incoming payload are independent. Preserve other domains and tests. Coordinated rollout only; legacy writers omit zero. NaN, infinity, out-of-float32-range inputs and signed-zero bit distinctions are outside this case.

**Oracle**

Missing and null producer input, explicit zero on the wire, negative values, float32 extrema, exact threshold and its immediate representable neighbors. Producer and consumer values differ. Eleven vectors × three runtimes.

**Wrong patches**

- `wrong-forgot-csharp.patch` (runtime): C# keeps a nonnullable speed request and fails when the new producer contract supplies null; the oracle rejects its nonzero exit.
- `wrong-zero-is-absent.patch` (oracle): Omits explicitly supplied zero; constructed payload presence must fail.
- `wrong-inclusive-threshold.patch` (oracle): Marks exactly 30 m/s as speeding.

**Weakness**

Finite float32 inputs only; no NaN, infinity or signed-zero distinction. This transfers the presence mechanism from the existing inventory case to different source and numeric behavior.

### fresh-telemetry-asset-rename

- Domain: telemetry. Label: **structural**.
- Change: Rename vehicle_id to asset_id at tag 1.

**Intended behavior (verbatim fixture policy)**

Rename VehicleTelemetry.vehicle_id to asset_id at wire field 1, retaining string type and all wire values. The external producer request key remains vehicle_id; write its exact value into asset_id. Consumer observations use asset_id instead of vehicle_id; preserve empty, Unicode, whitespace and escaped identifiers without trimming or normalization. Keep float32 speed_mps, expose the decoded float32 value as a JSON number; any decimal form that rounds to that float32 is accepted, and keep strict speeding >30.0. Producer input and incoming payload are independent. No json_name option is introduced. Other domains and tests are unchanged. NaN, infinity, out-of-float32-range inputs and signed-zero bit distinctions are outside this case.

**Oracle**

Retain external request.vehicle_id while using the new generated asset field and observation key. Empty, Unicode, significant whitespace, escaped IDs, independent incoming IDs, float32 extrema and strict >30 behavior. Eleven vectors × three runtimes.

**Wrong patches**

- `wrong-forgot-csharp.patch` (compile): C# retains the baseline generated-property contract and fails compilation.
- `wrong-old-observation-key.patch` (oracle): Still emits vehicle_id instead of asset_id.
- `wrong-trim-identifiers.patch` (oracle): Trims significant identifier whitespace on production.

**Weakness**

A simple same-tag rename on a second telemetry field; it reuses a known mechanism and makes no novelty claim. It adds no explicit json_name option and does not consume H7.

### fresh-inventory-quantity-unsigned

- Domain: inventory. Label: **semantic**.
- Change: Change quantity from int32 to uint32 with saturating producer conversion.

**Intended behavior (verbatim fixture policy)**

Change StockItem.quantity at field 2 from int32 to uint32 to represent nonnegative on-hand stock. Producer request.quantity remains a canonical signed decimal string in the signed int64 range; clamp it to [0, 4294967295] before encoding, without wrapping. Consumers expose the decoded uint32 quantity as a canonical decimal string. in_stock remains true exactly when decoded quantity is positive and decoded state is STOCK_STATE_UNSPECIFIED; quarantined and unknown states remain blocked. Preserve sku, optional label/route/state observations, labels and routing construction. Producer input and incoming payload are independent. No test edits. Coordinated rollout only; historical negative int32 payloads are outside the new input contract.

**Oracle**

Signed-int64 request extrema, negative-to-zero saturation, zero, int32 maximum, first value above int32, uint32 maximum and overflow above uint32. Check decimal JSON, stock predicate, quarantined/unknown states, repeated labels and both route fields. Ten vectors × three runtimes.

**Wrong patches**

- `wrong-forgot-csharp.patch` (compile): C# retains the baseline generated-property contract and fails compilation.
- `wrong-signed-ceiling.patch` (oracle): Clamps to int32 max instead of uint32 max.
- `wrong-wrap-negative.patch` (oracle): Uses unsigned wraparound instead of lower-bound clamping.

**Weakness**

Canonical decimal input strings only. Invalid strings and historical negative int32 payloads are excluded explicitly. This is distinct from widening signed integers: it changes signedness and clamps producers.

### fresh-inventory-state-bool

- Domain: inventory. Label: **semantic**.
- Change: Replace enum-valued state with a quarantine boolean.

**Intended behavior (verbatim fixture policy)**

Replace StockItem.state at field 3 from StockState enum with bool, retaining the field name and tag. false means not quarantined and true means quarantined. Producers accept optional JSON quarantined (boolean, default false) and encode it in state. Consumers report state_label UNSPECIFIED for false and QUARANTINED for true when include_state is requested, with no UNKNOWN label for this bool field. Under protobuf bool decoding every nonzero incoming varint, including historical unknown enum numbers, means true and must block stock. in_stock is true exactly when quantity is positive and state is false. Keep signed int32 quantity as a decimal string and preserve sku, label/route options and all other domains. Producer input and incoming payload are independent. Leave the now-unused enum declaration in the schema; do not edit generated code or tests. Coordinated rollout only.

**Oracle**

False/true producer values and absent default false; decoded wire values 0, 1, 2, 99, -1 and int32 max; signed quantity boundaries, zero and negative stock; optional state labels, labels and route preservation. Ten vectors × three runtimes.

**Wrong patches**

- `wrong-forgot-csharp.patch` (compile): C# retains the baseline generated-property contract and fails compilation.
- `wrong-producer-default-true.patch` (oracle): Defaults missing quarantined to true.
- `wrong-inverted-eligibility.patch` (oracle): Allows quarantined stock and blocks unquarantined stock.

**Weakness**

The schema retains an unused enum declaration. Protobuf boolean decoding intentionally collapses every historical nonzero enum value into quarantined. It does not add, rename or retire an enum member.

## Validation scope and current environment

The state-bool and speed-presence cases receive case-specific candidate anchors that point at lines the reference edits. The development cases did not receive this hint in the same way. The anchors are shared across models; their reason text appears in edit prompts, while block prompts show the selected candidate lines.

The independent oracle (`patchgen/fresh_oracle.py`) imports no generated bindings or reference recipes. Expected wire bytes are assembled independently. JSON result checks enforce types as well as values. For `speed_mps`, the oracle rounds the actual JSON number to float32 before comparing it with the expected decoded float32. Both shortest float32 decimal output and widened-double decimal output pass; strings and booleans fail. Review export rechecks the retained expected vectors, each runtime output, oracle/harness hashes, and, for entity presence, broker acknowledgements and malformed-payload evidence.

Runtime unit tests invoke the generator CLI (deterministic recipe for references, offline replay for controls) and apply all five references and fifteen wrong patches with `generator.apply_and_validate`, regenerate bindings with the pinned Buf-descriptor/local-plugin route, and compile real TypeScript and C# code. Telemetry/inventory use the production oracle vectors and CLI entry points. When loopback is forbidden, entity tests call the same Python/TypeScript/C# decoder functions used by subscribers; the C# function is invoked by a temporary reflection harness. The decoded observations are also passed through the real broker’s subscription, publication and acknowledgement logic in memory. The returned message is reserialized with each language’s actual generated codec and checked for preserved presence. This checks decoder, encoder and broker semantics without claiming HTTP transport coverage.

This authoring sandbox makes the checkout’s `.git` read-only, blocks loopback listeners, and cannot download packages. Tests therefore run in a writable `/tmp` copy with the exact working changes and installed dependencies. The offline Python environment has protobuf 6.33.5 rather than the deployment requirement 4.25.8. A full production pipeline attempt reached patch application and local codegen, then failed while installing the pinned protobuf package. The full socket-based pipeline/review test is skipped here; full end-to-end reference passes and subscriber transport evidence cannot honestly be claimed in this environment. Rerun that test in a normal environment before sealing.

Review-fix validation ran from `/tmp/schema-fresh-review-validation`, a writable copy containing the same source changes and installed dependency links. Evidence/history/held-out output directories, `summary.md` files and raw-response artifacts were excluded from the copy. No existing test was modified to hide sandbox errors.
